Код завершения, stdout/stderr, содержимое архивов и изменения на диске.

Ошибка на первом шаге останавливает цепочку. При отказе компилятора, архиватора библиотеки или финальной линковки pytest не запускается.

Что изменилось и зачем

02 / Сопровождение
01

Один вход через mise

Команды сборки, тестирования, форматирования и запуска собраны в mise.toml. Сложная сборка живёт в обычных Bash-скриптах.

Было: just + настройка окружения
Стало: mise управляет инструментами и задачами
02

Независимая подготовка

tmp_path и фикстуры работают на уровне одного сценария. Тесты не используют архивы, оставленные предыдущим тестом.

Было: общий каталог и порядок выполнения
Стало: каждый сценарий самодостаточен
03

Проверка другим читателем

Python создаёт входные TAR/ZIP и читает результат arc pack. Это помогает обнаружить ошибки, которые может скрыть один round trip.

Было: основа arc → arc
Стало: Python ↔ arc плюс round trips
04

Зависимости воспроизводимы

Python и uv закреплены в mise.toml; pytest и его зависимости — в uv.lock. Окружение tests/.venv отделено от программы.

Было: системный Python без тестового проекта
Стало: отдельный uv-проект с lock-файлом
05

Ошибка имеет имя

Pytest показывает конкретный сценарий и вариант формата. Помощник запуска добавляет команду, exit code и оба потока вывода.

Было: остановка большого скрипта на assert
Стало: точная диагностика отдельного случая
06

Свободнее менять реализацию

Тесты наблюдают CLI-контракт. Замена внутренних функций и структур не требует менять тест, если поведение пользователя сохранилось.

Было: компиляция внутренних C-харнессов
Стало: вызов обычной готовой бинарки

Улучшена проверяемость и сопровождаемость программы. Производственный код C не менялся; ускорение arc или исправление её функциональных ошибок здесь не заявляется.

05 / Ограничения

Что сохранено

  • Форматы, Unicode, ссылки, сохранение существующих файлов, выбор записей и контроль целостности.
  • Фикстуры повреждений CRC и заголовков, sparse TAR, ODC CPIO и локальный RAR.
  • Независимая API-проверка filekit отдельной задачей.
  • Обычный запуск и санитарные проверки C-бинарки.

Что не обещает этот набор

  • Внутренние API-контракты arc, fault injection, счётчики сравнений и тестовые подмены реализации удалены по выбранной границе чёрного ящика.
  • Python 3.13 не читает TAR.zst и 7z: для них используются round trips.
  • Временный каталог не является ОС-песочницей. Опасные пути направлены на контрольные файлы внутри него.
  • Создание symlink на Windows зависит от прав. Ограничения отмечаются явно.

Прежние «177 проверок» считали вызовы CLI/API. Новые 146 — самостоятельные сценарии, включая параметризацию. Эти числа не являются прямым сравнением покрытия.

Как пользоваться

06 / Рабочие команды
mise trust && mise install
mise run test
mise run test -- -k unpack
mise run check
mise run filekit:verify
mise run test -- --junitxml=/tmp/arc.xml

Окружение тестов уже установлено локально. Системные C-инструменты и libarchive остаются платформенными зависимостями. На Windows команды выполняются в MSYS2 UCRT64.
